キャッシュ課金の仕組み（自動有効・TTL 5分/1時間）

Kimi APIは同じリクエスト接頭辞のキャッシュ課金を自動で有効化します。公式の逐語は「The Kimi API automatically enables context caching billing for repeated request prefixes, with a default TTL (time-to-live) of 5m.」。つまり「使うかどうかを選ぶ」タイプではなく、同じ前置きを繰り返すワークロードでは何もしなくてもキャッシュ料金が発生し、ヒットすれば安くなるという設計です。

  • キャッシュヒット入力 $0.20（通常入力$2.00の10%）。ヒットした部分はキャッシュ単価だけがかかり、書き込み料金は二重取りされません（逐語「cached input is billed at the cache-hit price only, with no additional cache write charge」）。
  • 書き込みはTTLで単価が変わる。5分TTLが$2.00、1時間TTLが$4.00。長く保持したいほど高い、という素直な値付けです。
  • ヒットするとTTLは自動更新されます（公式ツールチップの逐語「each hit automatically refreshes the cache entry's TTL」）。
  • TTLの選び方とヒット率の上げ方は公式のコンテキストキャッシュのベストプラクティスにまとまっています。

Batch APIは標準価格の60%

公式の逐語は「kimi-k3.1-pro and kimi-k3 support batch inference for large-scale tasks that do not require real-time responses, billed at 60% of the standard price.」。リアルタイム性が要らない大量処理なら、入力$2.00→$1.20、出力$10.00→$6.00が目安になります（60%は当サイトの計算で、公式に個別のBatch単価表があるわけではありません。正確な値はBatchJob Pricingで確認してください）。

前世代Kimi K3との比較

  • 価格はK3.1 Proのほうが安い。入力$2.00（K3は$3.00）・出力$10.00（K3は$15.00）で、いずれも約33%減。
  • コンテキストは同じ1,048,576トークン。K3シリーズとして共通の上限です。
  • キャッシュ単価もK3.1 Proが安い。ヒット$0.20（K3は$0.30）、5分書込$2.00（同$3.00）、1時間書込$4.00（同$6.00）。
  • K3.1 ProはHighspeed版（同品質で高速・単価2倍）が用意されている点がK3との違いです。

使いどころと注意

  • 長い前置きを繰り返す処理と相性が良い。キャッシュが自動で効くため、同じシステムプロンプトや同じリポジトリ文脈を何度も流すエージェント用途では、実効単価が$2.00より下がります。
  • 1M近い長文を1回だけ流す用途はキャッシュが効きにくい。単発の巨大入力を避け、前置きを固定してヒット率を上げるほうが安く済みます。
  • バッチでよい処理は60%に寄せる。リアルタイム性が不要な要約・分類はBatch APIの対象です。
  • 通貨の取り違えに注意。中国語版は人民元、英語版は米ドルです。当サイトの比較表・計算機はUSD建てで統一しています。
  • K2系の終了に注意。2026年12月末でK2系は提供終了予定です。
