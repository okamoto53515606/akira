DeepSeek V4.1 Flash Guide

On 2026-09-10 DeepSeek officially released DeepSeek-V4.1-Flash, the smallest model in its new architecture family. Prices are far lower than V4 Pro, and image input (vision) is supported natively. This page covers pricing, specs and benchmarks verified only against DeepSeek's official pricing page and change log, plus setup in VS Code GitHub Copilot Chat and the relationship with V4 Pro (which DeepSeek says continues after 2026-09-14). See also the pricing comparison, the token calculator and the release timeline.

● Last updated: September 15, 2026  |  Primary source: official pricing page · Change Log (2026-09-10)  |  Retrieved: 2026-09-15

The short version

  • V4.1 Flash is the current workhorse. The model ID you pass in API requests is deepseek-flash (labels and options inside VS Code may differ as the extension is updated). 1M context, 384K max output, native image input.
  • Prices are far lower than V4 Pro. Input (cache miss) $0.15 off-peak / $0.30 peak; output $0.60 off-peak / $1.20 peak, in USD per 1M tokens. For reference, V4 Pro is $0.66 off-peak input and $1.98 off-peak output.
  • V4 Pro keeps running after 2026-09-14. DeepSeek had announced that deepseek-v4-pro requests would route to V4.1 Flash from 9/14, but it withdrew that notice. No rewrite is required (see below).

📘 cache hit vs cache miss: if the beginning of your prompt is still in DeepSeek's cache it counts as a cache hit (input $0.003 per 1M tokens — 1/50 of cache miss), otherwise it counts as a cache miss ($0.15). Sending the same long system prompt in the same order makes hits more likely.

V4 Pro keeps running (as of 2026-09-13)

Only what DeepSeek's official documentation states.

✅ DeepSeek says V4 Pro continues — the 9/14 routing notice was withdrawn

  • The 2026-09-10 V4.1 Flash announcement said DeepSeek would retire V4 Pro in an orderly manner and route deepseek-v4-pro requests to V4.1 Flash from 2026-09-14.
  • DeepSeek has since withdrawn that notice, replacing footnote (2) of the pricing page and the Change Log entry with: "In response to user demand, we have decided to continue providing API services for DeepSeek V4 Pro after September 14, 2026, with the billing method remaining unchanged."
  • deepseek-v4-pro keeps working and no code or API-key change is needed. A dedicated V4 Pro row (off-peak input $0.66 / output $1.98) is still on the official pricing page — it was never folded into V4.1 Flash pricing.
  • DeepSeek adds that it "will provide further notice should there be any changes," so future changes cannot be ruled out. Full details and a comparison live on the V4 Pro continuation page.

Setup in VS Code GitHub Copilot Chat (3 steps)

The steps the operator (okamo channel) actually used with the V4 family. Extension names and model-picker labels can change, so check the official docs too.

STEP 1

Get an API key

Sign up at platform.deepseek.com. Top up with PayPal or a credit card (VISA/Mastercard), then create an API key beginning with sk-. It is fully prepaid, with a $2 minimum top-up.

STEP 2

Install the extension

Install DeepSeek V4 for Copilot Chat (publisher: Vizards) from the VS Code Marketplace.

STEP 3

Configure and start

Run DeepSeek: Set API Key from the command palette (Cmd/Ctrl+Shift+P) to register your key, then pick a DeepSeek V4 model in the Copilot Chat model picker.

💡 If you set the model name in code, use deepseek-flash. Code that still points at deepseek-v4-pro keeps working as-is (V4 Pro continues; see above).

Run it on Azure AI Foundry (DeepSeek-V4-Flash-0731)

Beyond DeepSeek's own API, you can deploy DeepSeek models through Microsoft Azure's Azure AI Foundry (Microsoft Foundry). This walkthrough deploys DeepSeek-V4-Flash-0731, which Azure sells as a "Direct from Azure" model, using the Azure CLI, then verifies the endpoint with curl.

ℹ️ How DeepSeek-V4-Flash-0731 relates to V4.1 Flash: -0731 is the previous generation (released 2026-07-31; same architecture and size as V4-Flash-Preview, re-post-trained). On DeepSeek's own API the V4 Flash generation was retired into V4.1 Flash, but Azure AI Foundry still offers DeepSeek-V4-Flash-0731 as a Preview model (as of 2026-09-13). The Azure-side details come from Microsoft Learn. The command sequence was verified in practice by the operator (okamo channel) in September 2026.

Prerequisites

  • An Azure subscription with permission to create resources. Registering a resource provider requires Owner at the subscription level.
  • The Azure CLI (az). The az cognitiveservices commands ship in the CLI core, so no extra extension is needed on Azure CLI 2.60 or later.
  • You are signed in to the target subscription via az login.

Placeholders used below

Placeholders used in the commands
PlaceholderWhat to supply
<SUBSCRIPTION_ID_OR_NAME>The ID or name of the Azure subscription to use
<RESOURCE_GROUP>Resource group name (for example rg-deepseek)
<LOCATION>Region (for example eastus). Availability differs per model — check the model catalog in the Azure portal
<ACCOUNT_NAME>Azure AI Services account name. Must be globally unique (for example dsflash0731). The same value is reused for --custom-domain
<DEPLOYMENT_NAME>Deployment name (your choice). The model field in API calls takes the deployment name, not the model name (for example deepseek-0731)
<MODEL_VERSION>The model version string. Read the actual value from the az cognitiveservices account list-models call below — this page does not assert it
<API_KEY>The Azure AI Services account key (fetched from the CLI in the steps below)

Step 0 — Prepare the Azure CLI and register the resource provider

Doing this first avoids the MissingSubscriptionRegistration error later on.

# Check the Azure CLI version (2.60 or later recommended)
az version

# Sign in if needed
az login

# Select the target subscription
az account set --subscription "<SUBSCRIPTION_ID_OR_NAME>"

# Register the resource provider (prevents MissingSubscriptionRegistration)
az provider register --namespace Microsoft.CognitiveServices

# Check registration state (may take a few minutes to reach Succeeded)
az provider show --namespace Microsoft.CognitiveServices --query registrationState -o tsv

Step 1 — Create a resource group

az group create \
  --name "<RESOURCE_GROUP>" \
  --location "<LOCATION>"

Step 2 — Create the Azure AI Services account

Passing --custom-domain makes later endpoints take the form https://<ACCOUNT_NAME>.openai.azure.com/.

az cognitiveservices account create \
  --name "<ACCOUNT_NAME>" \
  --resource-group "<RESOURCE_GROUP>" \
  --kind AIServices \
  --sku S0 \
  --location "<LOCATION>" \
  --custom-domain "<ACCOUNT_NAME>" \
  --assign-identity \
  --allow-project-management true \
  --yes

Step 3 — Deploy DeepSeek-V4-Flash-0731

First list the available models and versions, then deploy with those values.

# List deployable DeepSeek models and their versions
az cognitiveservices account list-models \
  -n "<ACCOUNT_NAME>" -g "<RESOURCE_GROUP>" \
  --query "[?contains(name,'DeepSeek')].{name:name,format:format,version:version}" -o table

# Deploy the model (GlobalStandard SKU; see the capacity note below)
az cognitiveservices account deployment create \
  --name "<ACCOUNT_NAME>" \
  --resource-group "<RESOURCE_GROUP>" \
  --deployment-name "<DEPLOYMENT_NAME>" \
  --model-name "DeepSeek-V4-Flash-0731" \
  --model-version "<MODEL_VERSION>" \
  --model-format "DeepSeek" \
  --sku-name "GlobalStandard" \
  --sku-capacity 20

💡 --sku-capacity consumes quota measured in Tokens Per Minute (thousands). If capacity is insufficient the deployment can fail with InsufficientQuota — adjust the value, or request a quota increase in the Azure portal.

⚠️ --sku-capacity in practice (measured by the operator, 2026-09-15)

  • --sku-capacity 1 does deploy successfully, but it is too small: the API returned quota errors after only light use. The operator has run it at 20 since, without further trouble.
  • Set a value within the limit reported by az cognitiveservices usage list.
  • Do not consume the whole limit. Once it is used up, no quota is left to assign to other deployments in the same subscription.
# Check current quota usage and limit (LOCATION = deployment region)
az cognitiveservices usage list --location "<LOCATION>" -o table

Step 4 — Export the connection settings

# Endpoint (OpenAI-compatible) and API key
export AZURE_AI_ENDPOINT="https://<ACCOUNT_NAME>.openai.azure.com/openai/v1/"
export AZURE_AI_API_KEY="$(az cognitiveservices account keys list \
  --name "<ACCOUNT_NAME>" \
  --resource-group "<RESOURCE_GROUP>" \
  --query key1 -o tsv)"

# The API "model" field takes the deployment name
export DEPLOYMENT_NAME="<DEPLOYMENT_NAME>"

Step 5 — Verify connectivity with curl

curl -sS "$AZURE_AI_ENDPOINT/chat/completions" \
  -H "Content-Type: application/json" \
  -H "api-key: $AZURE_AI_API_KEY" \
  -X POST \
  -d '{
    "model": "'"$DEPLOYMENT_NAME"'",
    "messages": [
      { "role": "user", "content": "Reply with just OK." }
    ]
  }'

✅ A JSON response means the endpoint is live. Note that model must be the deployment name — passing the model name DeepSeek-V4-Flash-0731 can return a 404. If you would rather not export the key, use -H "api-key: <API_KEY>" inline. For Entra ID (formerly Azure AD) authentication, Microsoft's tutorial shows obtaining a token with scope https://ai.azure.com/.default via DefaultAzureCredential.

⚠️ If you hit MissingSubscriptionRegistration

It looks like this (HTTP 409 / Conflict). It simply means the Microsoft.CognitiveServices resource provider is not registered on the subscription — nothing is wrong with your resource request.

MissingSubscriptionRegistration
The subscription is not registered to use namespace 'Microsoft.CognitiveServices'.
  • Fix 1 (CLI): run az provider register --namespace Microsoft.CognitiveServices and wait until az provider show --namespace Microsoft.CognitiveServices --query registrationState -o tsv reports Registered (this can take a few minutes).
  • Fix 2 (portal): Azure portal → Subscriptions → Resource providers → select Microsoft.CognitiveServices → Register.
  • Permissions: registration requires Owner on the subscription. Ask an administrator if you lack it.
  • Official troubleshooting: Register a resource provider

FAQ

Q. How much does V4.1 Flash cost?

A. Per 1M tokens: input (cache miss) $0.15 off-peak / $0.30 peak, input (cache hit) $0.003 off-peak / $0.006 peak, output $0.60 off-peak / $1.20 peak. Peak hours are 01:00-04:00 and 06:00-10:00 UTC on weekdays only (JST 10:00-13:00 / 15:00-19:00); weekends are off-peak all day. Off-peak is half the peak rate.

Q. What happens if I keep calling deepseek-v4-pro after September 14?

A. It keeps working. DeepSeek states that, in response to user demand, it will continue providing API services for DeepSeek V4 Pro after September 14, 2026, with billing unchanged. The earlier announcement that requests would route to V4.1 Flash from 9/14 has been withdrawn. No code or API-key change is required.

Q. When will DeepSeek V4.1 Pro be released?

A. No release date has been announced as of 2026-09-13. The earlier note that the routing would last "until the future release of V4.1 Pro" has itself been replaced by the V4 Pro continuation notice. This site will update as soon as an official announcement appears.

Q. Can it read images?

A. Yes. V4.1 Flash is built on the new architecture family with native multimodal visual understanding, and the official feature table marks Vision as supported (V4 Pro did not). For a cross-model view of image, audio, video and PDF support, see the multimodal LLM guide.

Q. Can I keep using deepseek-v4-flash?

A. Those names are still accepted for compatibility, but the underlying models are retired: requests are served by V4.1 Flash and billed at the V4.1 Flash price. New code should use deepseek-flash.

Q. Context length and max output?

A. 1M-token context and 384K-token maximum output. Thinking mode supports both non-thinking and thinking, with thinking as the default.
