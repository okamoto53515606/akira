DeepSeek V4.1 Flash Guide

On 2026-09-10 DeepSeek officially released DeepSeek-V4.1-Flash, the smallest model in its new architecture family. Prices are far lower than V4 Pro, and image input (vision) is supported natively. This page covers pricing, specs and benchmarks verified only against DeepSeek's official pricing page and change log, plus setup in VS Code GitHub Copilot Chat and the relationship with V4 Pro (which DeepSeek says continues after 2026-09-14). See also the pricing comparison, the token calculator and the release timeline.

The short version

  • V4.1 Flash is the current workhorse. The model ID you pass in API requests is deepseek-flash (labels and options inside VS Code may differ as the extension is updated). 1M context, 384K max output, native image input.
  • Prices are far lower than V4 Pro. Input (cache miss) $0.15 off-peak / $0.30 peak; output $0.60 off-peak / $1.20 peak, in USD per 1M tokens. For reference, V4 Pro is $0.66 off-peak input and $1.98 off-peak output.
  • V4 Pro keeps running after 2026-09-14. DeepSeek had announced that deepseek-v4-pro requests would route to V4.1 Flash from 9/14, but it withdrew that notice. No rewrite is required (see below).

Get an API key

Sign up at platform.deepseek.com. Top up with PayPal or a credit card (VISA/Mastercard), then create an API key beginning with sk-. It is fully prepaid, with a $2 minimum top-up.

Install the extension

Running it on Microsoft Foundry (Azure) — deploying DeepSeek-V4.1-Flash with the CLI (measured 2026-09-28)

Prerequisites

  • An Azure subscription where you can create resources (registering a resource provider requires Owner)
  • The Azure CLI (az). The az cognitiveservices commands ship with core, so Azure CLI 2.60+ needs no extra extension
  • You are signed in to the target subscription with az login

Placeholders used below

Placeholders used in the commands
PlaceholderMeaning / value to supply
<SUBSCRIPTION_ID_OR_NAME>ID or name of the Azure subscription to use
<RESOURCE_GROUP>Resource group name (e.g. rg-deepseek)
<LOCATION>Region (e.g. eastus). Availability differs per model — check the Azure portal model catalog
<ACCOUNT_NAME>Azure AI Services account name, which must be globally unique (e.g. dsflash0928). The same value is used for --custom-domain
<DEPLOYMENT_NAME>Your deployment name (free choice). The model field in API calls takes this deployment name, not the model name (e.g. ds-flash-01)
<MODEL_VERSION>Model version string. Measured as 2026-09-10 on 2026-09-28, but names and versions differ by environment (subscription/region) — always confirm with list-models below
<API_KEY>Key of the Azure AI Services account (fetched from the CLI in the steps below)

Step 0 — Prepare the Azure CLI and register the resource provider

Doing this first avoids the MissingSubscriptionRegistration error later.

# Check the Azure CLI version (2.60+ recommended)
az version

# Sign in if needed
az login

# Select the subscription to use
az account set --subscription "<SUBSCRIPTION_ID_OR_NAME>"

# Register the resource provider (avoids MissingSubscriptionRegistration)
az provider register --namespace Microsoft.CognitiveServices

# Check registration state (can take a few minutes to become Succeeded)
az provider show --namespace Microsoft.CognitiveServices --query registrationState -o tsv

Step 1 — Create a resource group

az group create \
  --name "<RESOURCE_GROUP>" \
  --location "<LOCATION>"

Step 2 — Create the Azure AI Services account

With --custom-domain, the endpoint becomes https://<ACCOUNT_NAME>.openai.azure.com/.

az cognitiveservices account create \
  --name "<ACCOUNT_NAME>" \
  --resource-group "<RESOURCE_GROUP>" \
  --kind AIServices \
  --sku S0 \
  --location "<LOCATION>" \
  --custom-domain "<ACCOUNT_NAME>" \
  --assign-identity \
  --allow-project-management true \
  --yes

Step 3 — Deploy DeepSeek-V4.1-Flash

List the models actually available to your account, then deploy with those values. Checking the real thing first is how you stay safe while the docs lag behind.

# List deployable DeepSeek models and their versions
az cognitiveservices account list-models \
  -n "<ACCOUNT_NAME>" -g "<RESOURCE_GROUP>" \
  --query "[?contains(name,'DeepSeek')].{name:name,format:format,version:version}" -o json

# Deploy (SKU is GlobalStandard; see the notes below for --sku-capacity)
az cognitiveservices account deployment create \
  --name "<ACCOUNT_NAME>" \
  --resource-group "<RESOURCE_GROUP>" \
  --deployment-name "<DEPLOYMENT_NAME>" \
  --model-name "DeepSeek-V4.1-Flash" \
  --model-version "<MODEL_VERSION>" \
  --model-format "DeepSeek" \
  --sku-name "GlobalStandard" \
  --sku-capacity 20

# Confirm the deployment (model name, SKU, capacity)
az cognitiveservices account list-deployments \
  -n "<ACCOUNT_NAME>" -g "<RESOURCE_GROUP>" \
  --query "[].{name:name,model:properties.model.name,version:properties.model.version,sku:sku}" -o json

💡 On 2026-09-28, list-models returned DeepSeek-V4.1-Flash (version 2026-09-10, format DeepSeek) and the deployment went through with those values. Version strings can differ by environment, so don't paste the value from this article — use what list-models returns.

⚠️ --sku-capacity in practice (measured by the operator, 2026-09-28)

  • --sku-capacity 1 does deploy successfully, but it was so small that a few API calls hit quota errors. In our measurement, 20 was stable (a short trial in one environment; the capacity you need varies with load, so this is not a general recommendation).
  • Capacity maps to TPM (tokens per minute). Microsoft Learn states that TPM is assigned in increments of 1,000 and RPM is derived from TPM, varying by model (Foundry Models quotas and limits).
  • Measured on a capacity-20 deployment via response headers: x-ratelimit-limit-requests: 20 (RPM) and x-ratelimit-limit-tokens: 20000 (TPM). Always confirm your own limits from these headers or usage list after deploying.
  • Quota is consumed per subscription. For Global Standard, deployments of the same model and version share a single quota pool across all regions, so adding the same model in another region competes for the same pool (same Learn page).
  • Don't consume the whole limit. If you do, you cannot allocate quota to other deployments in the same subscription.
  • Calls above the limit return HTTP 429. Use exponential backoff with retries, and request a quota increase if it is a recurring problem (same Learn page).
# Check current quota usage and limits (LOCATION = your deployment region)
az cognitiveservices usage list --location "<LOCATION>" -o table

⚠️ There is no deployment update in the core CLI (changing capacity)

  • Microsoft Learn's az cognitiveservices account deployment lists create / list / show — core has no update (it exists only in the Preview foundry-cost-control extension).
  • So changing capacity practically means re-running deployment create with the new value (measured 2026-09-28).
  • Editing the deployment in the Azure portal is the safest fallback. Subcommand layouts change, so check the current Learn page before you run anything.

Step 4 — Export the connection settings

# Endpoint (OpenAI-compatible) and API key
export AZURE_AI_ENDPOINT="https://<ACCOUNT_NAME>.openai.azure.com/openai/v1/"
export AZURE_AI_API_KEY="$(az cognitiveservices account keys list \
  --name "<ACCOUNT_NAME>" \
  --resource-group "<RESOURCE_GROUP>" \
  --query key1 -o tsv)"

# The API's model field takes the deployment name
export DEPLOYMENT_NAME="<DEPLOYMENT_NAME>"

Step 5 — Verify with curl (and read the rate-limit headers)

curl -sS -D - "$AZURE_AI_ENDPOINT/chat/completions" \
  -H "Content-Type: application/json" \
  -H "api-key: $AZURE_AI_API_KEY" \
  -X POST \
  -d '{
    "model": "'"$DEPLOYMENT_NAME"'",
    "messages": [
      { "role": "user", "content": "Reply with just OK." }
    ]
  }'

✅ A JSON response means you are connected. Note that model takes the deployment name (passing the model name DeepSeek-V4.1-Flash can return a 404). -D - prints the rate-limit headers (x-ratelimit-limit-requests / x-ratelimit-limit-tokens), so you can confirm your capacity is in effect. If you prefer not to keep keys in environment variables, pass -H "api-key: <API_KEY>" directly. For Entra ID (formerly Azure AD) auth, the official tutorial's approach with DefaultAzureCredential and scope https://ai.azure.com/.default also works.

⚠️ Pitfalls specific to the Azure route

  • DeepSeek's own thinking parameter does not work on Azure. In our measurement, including {"thinking": {"type": "enabled"}} returned HTTP 400; only reasoning_effort was accepted. If you port code from the first-party API, revisit those lines first.
  • The Foundry blog describes this model's reasoning effort as a continuous setting from 1 to 100, while the first-party API uses three levels (low / high / max). The parameter systems differ — start small when migrating.
  • The catalog card states Context window 1000k / Token limits 128k output, which conflicts with the 384K max output DeepSeek publishes. Verify real limits in your own account.
  • Model names and versions vary by environment — use list-models rather than hard-coding values from this article.
  • It is Preview (public preview): SKUs, pricing, quotas and parameters can change without notice.

⚠️ If you hit MissingSubscriptionRegistration

The error looks like this (HTTP 409 / Conflict). The subscription simply has not registered the Microsoft.CognitiveServices resource provider — nothing is wrong with your resource definition.

MissingSubscriptionRegistration
The subscription is not registered to use namespace 'Microsoft.CognitiveServices'.
  • Fix 1 (CLI): run az provider register --namespace Microsoft.CognitiveServices, then wait until az provider show --namespace Microsoft.CognitiveServices --query registrationState -o tsv returns Registered (can take a few minutes).
  • Fix 2 (portal): Azure portal → Subscriptions → Resource providers → select Microsoft.CognitiveServices → Register.
  • Permissions: registration requires Owner on the subscription. Ask an administrator otherwise.
  • Official troubleshooting: Register a resource provider

FAQ

Q. How much does V4.1 Flash cost?

A. Per 1M tokens: input (cache miss) $0.15 off-peak / $0.30 peak, input (cache hit) $0.003 off-peak / $0.006 peak, output $0.60 off-peak / $1.20 peak. Peak hours are 01:00-04:00 and 06:00-10:00 UTC on weekdays only (JST 10:00-13:00 / 15:00-19:00); weekends are off-peak all day. Off-peak is half the peak rate.

Q. What happens if I keep calling deepseek-v4-pro after September 14?

A. It keeps working. DeepSeek states that, in response to user demand, it will continue providing API services for DeepSeek V4 Pro after September 14, 2026, with billing unchanged. The earlier announcement that requests would route to V4.1 Flash from 9/14 has been withdrawn. No code or API-key change is required.

Q. When will DeepSeek V4.1 Pro be released?

A. No release date has been announced as of 2026-09-13. The earlier note that the routing would last "until the future release of V4.1 Pro" has itself been replaced by the V4 Pro continuation notice. This site will update as soon as an official announcement appears.

Q. Can it read images?

A. Yes. V4.1 Flash is built on the new architecture family with native multimodal visual understanding, and the official feature table marks Vision as supported (V4 Pro did not). For a cross-model view of image, audio, video and PDF support, see the multimodal LLM guide.

Q. Can I keep using deepseek-v4-flash?

A. Those names are still accepted for compatibility, but the underlying models are retired: requests are served by V4.1 Flash and billed at the V4.1 Flash price. New code should use deepseek-flash.

Q. Context length and max output?

A. 1M-token context and 384K-token maximum output. Thinking mode supports both non-thinking and thinking, with thinking as the default.

Q. Can I run DeepSeek V4.1 Flash on Azure (Microsoft Foundry)?

A. Yes. In a measurement on 2026-09-28 we deployed DeepSeek-V4.1-Flash (version 2026-09-10) with az cognitiveservices account deployment create and got responses from the OpenAI-compatible endpoint. It is Preview (public preview), and as of 2026-10-05 Azure's pricing page had not been updated yet (Microsoft Learn's list as of 2026-09-29). The full walkthrough, including real capacity figures, is in the Microsoft Foundry section.

Q. What does the Azure route cost?

A. Per Microsoft's Foundry blog (updated 2026-09-25): Direct from Azure is input $0.30 / output $1.20 / cached input $0.006, and Fireworks on Foundry is input $0.37 / output $1.50 / cached input $0.007 (USD per 1M tokens). Direct from Azure matches DeepSeek's peak rates, with no off-peak discount. Because Azure's pricing page has no V4.1-Flash row yet, confirm in the portal before committing.

Q. Does my code work as-is if I move to Azure?

A. Mostly, with two fixes. ① DeepSeek's own thinking parameter returns 400 on Azure; only reasoning_effort is accepted (measured 2026-09-28). ② The effort scale differs — the Foundry blog describes a continuous 1–100 setting, while the first-party API uses low/high/max. The endpoint is OpenAI-compatible (/openai/v1), so apart from those two points it is largely a drop-in swap.
