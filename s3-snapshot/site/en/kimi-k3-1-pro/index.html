Kimi K3.1 Pro

Moonshot AI's flagship, with a 1,048,576-token context window and standard API pricing of $2.00 input / $10.00 output per 1M tokens. It is cheaper than the previous-generation Kimi K3 ($3.00/$15.00), and prompt-cache billing is enabled automatically.

In short

  • Launched; we read it as GA. The pricing page has a row for the model and the banner reads "Kimi K3.1 Pro has launched!", with no preview, waitlist or limited-access wording. The page never uses the term GA, so this is our reading; the table below is that row, verbatim.
  • The API model name is kimi-k3.1-pro, and a faster same-quality variant, kimi-k3.1-pro-highspeed, sits in the same table.
  • Standard pricing is $2.00 input / $10.00 output / $0.20 cached input per 1M tokens. The previous generation Kimi K3 is $3.00/$15.00, so K3.1 Pro is the cheaper model.
  • Context is 1,048,576 tokens for the whole K3 series (verbatim: "All K3 series models support a 1,048,576-token context window.").
  • Cache billing is on by default (default TTL 5 minutes). Writes are priced separately for the 5-minute and 1-hour TTLs.
  • Batch API is 60% of the standard price for kimi-k3.1-pro and kimi-k3.

How cache billing works (automatic, 5-minute and 1-hour TTLs)

The Kimi API turns on context caching billing automatically for repeated request prefixes. Verbatim: "The Kimi API automatically enables context caching billing for repeated request prefixes, with a default TTL (time-to-live) of 5m." So this is not an opt-in feature that you enable per request; workloads that resend the same prefix get cache billing without any configuration.

  • Cached input is $0.20, a tenth of the $2.00 input rate. Cached tokens are billed at the cache-hit price only, with no additional cache write charge (verbatim: "cached input is billed at the cache-hit price only, with no additional cache write charge").
  • Writes are priced by TTL: $2.00 for the 5-minute tier and $4.00 for the 1-hour tier. Holding a prefix longer costs more.
  • Each hit refreshes the cache entry's TTL automatically.
  • See the official context caching best practices for choosing a TTL tier.

Batch API is 60% of the standard price

Verbatim: "kimi-k3.1-pro and kimi-k3 support batch inference for large-scale tasks that do not require real-time responses, billed at 60% of the standard price." For non-realtime bulk work that implies roughly $1.20 input and $6.00 output, but 60% is our arithmetic; the official BatchJob pricing page is the authoritative table.

Compared with Kimi K3

  • K3.1 Pro is cheaper on every line: $2.00 vs $3.00 input and $10.00 vs $15.00 output, about 33% lower on both.
  • Context is identical at 1,048,576 tokens, a K3-series-wide limit.
  • Cache rates are lower too: $0.20 vs $0.30 cached input, $2.00 vs $3.00 for 5-minute writes, $4.00 vs $6.00 for 1-hour writes.
  • K3.1 Pro adds a Highspeed variant (same quality, faster, 2x the price).

Where it fits, and what to watch

  • Good for repeated long prefixes. Because caching is automatic, agent workloads that resend the same system prompt or repository context pay below the $2.00 headline rate.
  • One-shot huge inputs get little cache benefit. Keeping the prefix stable beats streaming a different 1M-token document each call.
  • Send non-realtime batches through Batch API for the 60% rate.
  • Watch the currency. The Chinese page is in yuan, the English page in USD; our tables and calculator use USD.
  • Plan the K2 migration before the end of December 2026.
