最初にこれを済ませておくと、後の手順で MissingSubscriptionRegistration エラーに当たりません。

STEP 2 — Azure AI Services アカウントを作成

--custom-domain を指定すると、以降のエンドポイントが https://<ACCOUNT_NAME>.openai.azure.com/ の形式になります。

az cognitiveservices account create \

  --resource-group "<RESOURCE_GROUP>" \
  --kind AIServices \
  --sku S0 \
  --location "<LOCATION>" \
  --custom-domain "<ACCOUNT_NAME>" \
  --assign-identity \
  --allow-project-management true \

STEP 3 — DeepSeek-V4.1-Flash をデプロイ

まず利用可能なモデルとバージョンを確認し、その値でデプロイします。この「実物を確認してからデプロイ」が、ドキュメントが遅れている時期でも安全に進めるコツです。

# デプロイ可能な DeepSeek 系モデルとバージョンを確認
az cognitiveservices account list-models \
  -n "<ACCOUNT_NAME>" -g "<RESOURCE_GROUP>" \
  --query "[?contains(name,'DeepSeek')].{name:name,format:format,version:version}" -o json

# モデルをデプロイ（SKU は GlobalStandard。--sku-capacity の値は下の注意書きを参照）
az cognitiveservices account deployment create \
  --name "<ACCOUNT_NAME>" \
  --resource-group "<RESOURCE_GROUP>" \
  --deployment-name "<DEPLOYMENT_NAME>" \
  --model-name "DeepSeek-V4.1-Flash" \
  --model-version "<MODEL_VERSION>" \
  --model-format "DeepSeek" \
  --sku-name "GlobalStandard" \
  --sku-capacity 20

# デプロイ結果の確認（モデル名・SKU・capacity が入っているか）
az cognitiveservices account list-deployments \
  -n "<ACCOUNT_NAME>" -g "<RESOURCE_GROUP>" \
  --query "[].{name:name,model:properties.model.name,version:properties.model.version,sku:sku}" -o json

💡 2026-09-28 の実測では list-models に DeepSeek-V4.1-Flash（version 2026-09-10、format DeepSeek）が返り、そのままデプロイできました。 バージョン文字列は環境で違うことがあるため、記事の値をそのまま貼らず、list-models の戻り値を使ってください。

⚠️ --sku-capacity の実運用（運営者実測・2026-09-28）

  • --sku-capacity 1 でもデプロイ自体は成功しますが、少なすぎて API を少し使っただけでクォータ不足のエラーになりました。実測では 20 に引き上げてから安定しています（短時間の試行での観測で、負荷条件により必要な容量は変わります。一般に推奨される値ではありません）。
  • capacity は TPM（tokens per minute）に対応します。Microsoft Learn には「TPM は 1,000 単位で割り当て、RPM は TPM から導出されモデルによって変わる」と記載されています（Foundry Models quotas and limits）。
  • 実測（capacity 20 のデプロイで応答ヘッダを確認）: x-ratelimit-limit-requests: 20（RPM）／x-ratelimit-limit-tokens: 20000（TPM）。自分の環境の上限は、デプロイ後にこのヘッダか usage list で確認するのが確実です。
  • クォータはサブスクリプション単位で消費されます。Global Standard は同じモデル・同じバージョンのデプロイが全リージョンで1つのプールを共有するため、同じモデルを別リージョンにもう1本立てると同じ枠を取り合います（同 Learn）。
  • 上限まで使い切らないでください。使い切ると、同じサブスクリプションで他のデプロイにクォータを割り当てられなくなります。
  • 上限を超えた呼び出しは HTTP 429 で返ります。指数バックオフ＋リトライで対処し、恒常的に足りない場合はクォータ増加を申請してください（同 Learn）。
# 現在のクォータ使用量と上限を確認（LOCATION はデプロイ先リージョン）
az cognitiveservices usage list --location "<LOCATION>" -o table

⚠️ core CLI に deployment update はありません（capacity を変えるときの落とし穴）

  • Microsoft Learn の az cognitiveservices account deployment にあるサブコマンドは create / list / show で、update は core にはありません（Preview の拡張機能 foundry-cost-control 版としてのみ提供）。
  • したがって capacity の変更も、同じ deployment create を新しい値で再実行するのが実務的な手順です（2026-09-28 実測）。
  • 迷ったら Azure ポータルの「デプロイ」画面から編集するのが確実です。CLI のサブコマンド構成は変わることがあるため、実行前に必ず Learn の最新ページを確認してください。

STEP 4 — 接続情報を環境変数に入れる

# エンドポイント（OpenAI 互換）と API キーを取得
export AZURE_AI_ENDPOINT="https://<ACCOUNT_NAME>.openai.azure.com/openai/v1/"
export AZURE_AI_API_KEY="$(az cognitiveservices account keys list \
  --name "<ACCOUNT_NAME>" \
  --resource-group "<RESOURCE_GROUP>" \
  --query key1 -o tsv)"

# API 呼び出しの model に入れるのはデプロイ名
export DEPLOYMENT_NAME="<DEPLOYMENT_NAME>"

STEP 5 — curl で疎通確認（レート制限ヘッダも見る）

curl -sS -D - "$AZURE_AI_ENDPOINT/chat/completions" \
  -H "Content-Type: application/json" \
  -H "api-key: $AZURE_AI_API_KEY" \
  -X POST \
  -d '{
    "model": "'"$DEPLOYMENT_NAME"'",
    "messages": [
      { "role": "user", "content": "Reply with just OK." }
    ]
  }'

✅ 応答 JSON が返れば疎通完了です。model にデプロイ名を渡している点に注意してください（モデル名 DeepSeek-V4.1-Flash を渡すと 404 などになることがあります）。 -D - を付けるとレート制限ヘッダ（x-ratelimit-limit-requests / x-ratelimit-limit-tokens）がそのまま見えるので、capacity が意図どおり効いているか確認できます。 環境変数にキーを置きたくない場合は -H "api-key: <API_KEY>" を直接指定します。 Entra ID（旧 Azure AD）で認証する場合は、公式チュートリアルにあるとおり DefaultAzureCredential 等でスコープ https://ai.azure.com/.default のトークンを取得する方式も使えます。

⚠️ Azure 経由で固有のつまずきどころ

  • DeepSeek 固有の thinking パラメータは Azure 側では通りません。実測では {"thinking": {"type": "enabled"}} を含めると HTTP 400 が返り、reasoning_effort だけが受け付けられました。自社 API のコードをそのまま流用するときは、この2行を必ず見直してください。
  • Foundry ブログの説明では、このモデルの推論努力は「1〜100 の連続値」で制御するとされています（自社 API は low / high / max の3段階）。パラメータの体系が違うので、移行時はいったん小さく試してください。
  • モデルカタログのカード表記は Context window 1000k / Token limits 128k output です。DeepSeek 側が公表している最大出力 384K と食い違うため、実際の上限は自分のアカウントで確認してください。
  • モデル名・バージョンは環境依存です。記事の値で固定せず list-models を使ってください。
  • Preview（public preview）である点も重要です。SKU・料金・クォータ・パラメータが予告なく変わることがあります。

⚠️ MissingSubscriptionRegistration が出たら

次のようなエラーです（HTTP 409 / Conflict）。サブスクリプションで Microsoft.CognitiveServices リソースプロバイダーが未登録なだけなので、リソース作成側の問題ではありません。

MissingSubscriptionRegistration
The subscription is not registered to use namespace 'Microsoft.CognitiveServices'.
  • 対処1（CLI）: az provider register --namespace Microsoft.CognitiveServices を実行し、az provider show --namespace Microsoft.CognitiveServices --query registrationState -o tsv が Registered になるまで待ちます（数分かかることがあります）。
  • 対処2（ポータル）: Azure ポータル →「サブスクリプション」→「リソースプロバイダー」→ Microsoft.CognitiveServices を選び「登録」。
  • 権限: 登録にはサブスクリプションの Owner 権限が必要です。権限が無い場合は管理者に依頼してください。
  • 公式のトラブルシューティング: Register a resource provider

よくある質問

Q. DeepSeek V4.1 Flash の料金はいくらですか？

A. 1Mトークンあたり、入力（cache miss）がオフピーク $0.15・ピーク $0.30、入力（cache hit）がオフピーク $0.003・ピーク $0.006、出力がオフピーク $0.60・ピーク $1.20 です。ピークは平日の 01:00-04:00 UTC と 06:00-10:00 UTC（日本時間 10:00-13:00 / 15:00-19:00）で、土日は終日オフピーク。オフピークはピークの半額です。

Q. 9月14日以降に deepseek-v4-pro を使うとどうなりますか？

A. 引き続き使えます。DeepSeek は「ユーザーの要望を受け、2026-09-14 以降も V4 Pro の API サービス提供を継続し、課金方法は変更しない」と告知しました。以前の「9/14 以降は V4.1 Flash へルーティング」という予告は撤回済みです。コードや API キーの書き換えは不要です。

Q. DeepSeek V4.1 Pro はいつリリースされますか？

A. 2026-09-13 時点で公式にリリース時期は発表されていません。なお以前の注記には「将来 V4.1 Pro がリリースされるまで（until V4.1 Pro is released in the future）」という記述がありましたが、その注記自体が V4 Pro 提供継続の文面に差し替えられています。当サイトでも公式発表が出た時点で更新します。

Q. 画像を読めますか？

A. はい。V4.1 Flash は新アーキテクチャ世代でネイティブのマルチモーダル視覚理解に対応し、公式の機能表でも Vision が「✓」です（旧 V4 Pro は非対応）。画像を含むモデル横断の比較は マルチモーダル対応LLM一覧を参照してください。

Q. deepseek-v4-flash のままでも動きますか？

A. 一時的な互換のために受理されますが、対応する旧モデルは退役済みで、リクエストは V4.1 Flash が処理し V4.1 Flash の価格で課金されます。新規実装では deepseek-flash を指定してください。

Q. コンテキスト長と最大出力は？

A. コンテキスト長 1M トークン、最大出力 384K トークンです。thinking mode は non-thinking と thinking の両方に対応し、thinking が既定です。

Q. Azure（Microsoft Foundry）でも DeepSeek V4.1 Flash を使えますか？

A. 使えます。2026-09-28 の実測で、DeepSeek-V4.1-Flash（version 2026-09-10）を az cognitiveservices account deployment create でデプロイし、OpenAI 互換エンドポイントから応答を取得できました。ただし Preview（public preview）で、Microsoft Learn のモデル一覧（2026-09-29 時点）と Azure の料金ページ（2026-10-05 時点）はまだ未更新です。手順と capacity の実数値はAzure AI Foundry の節にまとめています。

Q. Azure 経由の料金はいくらですか？

A. Microsoft の Foundry ブログ（2026-09-25 更新）の表では、Direct from Azure が入力 $0.30 / 出力 $1.20 / cached input $0.006、Fireworks on Foundry が入力 $0.37 / 出力 $1.50 / cached input $0.007（USD / 1Mトークン）。Direct from Azure は DeepSeek 自社 API のピーク単価と同水準で、自社 API のような時間帯割引はありません。Azure の料金ページに V4.1-Flash の行がまだ無いため、契約前にポータルで確認してください。

Q. Azure に移すとコードはそのまま動きますか？

A. 概ね動きますが、2点だけ直しが必要です。① DeepSeek 固有の thinking パラメータは Azure 側では 400 になり、reasoning_effort のみ受け付けます（2026-09-28 実測）。② 思考の強さの体系が違い、Foundry ブログは「1〜100 の連続値」と説明しています（自社 API は low/high/max）。エンドポイントは OpenAI 互換（/openai/v1）なので、この2点以外はほぼ置き換えで済みます。
