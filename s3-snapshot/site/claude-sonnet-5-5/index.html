まず結論 — 何が新しいのか

  • 値下げではなく世代更新です。入力$2・出力$10は、前世代のClaude Sonnet 5（$2/$10）と同じ。Opus 5.5のように前世代より安くなったモデルとは性格が違います。
  • ただしキャッシュ読込は$0.20→$0.10に半減しています。入力・出力の単価は前世代と同じですが、長い文脈を使い回すRAG・エージェント用途では実効コストが下がります（公式料金ページで2026-10-09に再確認）。
  • 仕様はOpus 5.5とほぼ同じ水準（当サイトの比較）。コンテキスト1M・最大出力128K・知識カットオフ2026年6月。上位モデルと同じ土俵です。
  • thinkingは「Adaptive」で既定ON、既定エフォートはhigh。ただしOpus 5.5の「Adaptive (always on)」とは書き分けられており、Sonnet 5.5には事前思考を切る最低設定between_toolsが用意されています。
  • 公式ページにベンチマークの記載はありません。Opus 5.5の発表記事に載っていたベンチ表のような数値は、Sonnet 5.5の概要ページには見当たりません。当サイトでは数値を作らずに「未掲載」と書きます。

公式が示しているキャッシュの一般ルール

“5-minute cache write | 1.25x base input price … 1-hour cache write | 2x base input price … Cache read (hit) | 0.1x base input price (0.025x on Claude Fable 5.1 and Claude Mythos 5.1; 0.05x on Claude Opus 5.5 and Claude Sonnet 5.5)” — Claude Platform Docs「Pricing」（2026-10-09 確認）
  • Sonnet 5.5のキャッシュ読込は入力の5%（$0.10）で、標準の10%より深い割引です。公式の逐語は「0.05x on Claude Opus 5.5 and Claude Sonnet 5.5」。実額でもFable 5.1の$0.25・Opus 5.5の$0.20より安い$0.10です。割引率の深さと実額の安さは別物なので、両方を見てください。
  • Batch APIは入力・出力とも50%割引と公式ページに記載があります。
  • 米国限定推論は1.1倍。逐語:「For Claude 4.6 and later models, specifying US-only inference through the inference_geo parameter incurs a 1.1x multiplier on all token pricing categories, including input tokens, output tokens, cache writes, and cache reads.」
  • 提携プラットフォームは独自の地域価格。逐語:「Partner-operated platforms (Bedrock and Google Cloud) have independent regional pricing.」

thinking の扱い — Opus 5.5と書き分けられている

Sonnet 5.5の概要ページには、thinkingについて次の逐語があります。

“Adaptive thinking is on by default. The lowest thinking setting is between_tools, which turns off up-front thinking. It works at high effort or below.” — Claude Platform Docs「Claude Sonnet 5.5」（2026-10-09確認）

事前思考を切れるか切れる（最低設定between_toolsでup-front thinkingがオフ。high以下のエフォートで動作）切れない（当サイトのOpus 5.5解説で扱った「thinking can't be disabled」）
🔍 読み方: 同じ「Adaptive」でも、Sonnet 5.5には思考を減らす逃げ道があり、Opus 5.5にはありません。単純なタスクを大量に流す用途では、この差が出力トークン量＝コストに効きます。「Sonnetの方が安い」理由は単価だけではない、という点に注意してください。

向いている場面 / 注意すべき場面

  • コストを抑えた大量処理: 入力$2・キャッシュ読込$0.10は、1Mコンテキスト級のモデルとしては低い側です（当サイトの比較結果）（当サイトの料金比較に掲載しているモデルとの比較）。長い文脈を繰り返し送るRAGやエージェントでも単価が効きます。
  • thinkingを絞りたい処理: between_toolsまで下げられるので、分類・抽出のような単純作業で出力トークンを抑えられます。Opus 5.5ではできない芸当です。
  • 「Sonnet 5から乗り換える」場合: 単価は同じなので、乗り換えの判断材料は性能と出力トークン量になります。ただしSonnet 5.5のベンチマークは公式に未掲載なので、数値比較はできません。自前の評価セットでの確認を推奨します。
  • 監査・契約が絡む用途: ZDR / ZOA / 学習条項 / データ所在はモデル概要ページには書かれていません。ZOA・4要件の各ページで、ベンダー別の確認先を先に押さえてください。
  • 速度優先の用途: 公式表のLatencyはFast（Opus 5.5はModerate）と記載されています。ただし具体的なレイテンシ値・スループットの数値は未確認です。
