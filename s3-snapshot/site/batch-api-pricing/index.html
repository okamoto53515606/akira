Batch API割引の横断比較 【2026年11月版】

Batch APIとは: 大量のリクエストを非同期でまとめて送り、できあがった結果を後から受け取る仕組みです。待ち時間と引き換えに、単価が通常の50〜60%になります。

大量のリクエストを非同期でまとめて流すと、単価がどこまで下がるかを1つの表にまとめました。リアルタイム性を捨てる代わりに単価を下げる仕組みなので、「待てる処理かどうか」が導入判断の分かれ目になります。通常単価はLLM API料金比較、同じ前置きを使い回すときの単価はプロンプトキャッシュ料金の横断比較を参照してください。

●最終更新: 2026年11月12日 | 各社公式ページを2026-11-12に取得し、引用は逐語ベース。割引率を通常単価に当てはめた金額は「計算値」と明記しています。

先に押さえる3点

  • 主要3社は「50%減」で並んでいる。OpenAI・Anthropic・Googleはいずれも通常比50%減。割引率だけを見れば横並びなので、差がつくのは締切・保持期間・上限のほうです。
  • 割引率はモデル単位で決まる会社がある。xAIはモデルごとに割引率が異なり、表に載っていないモデルは「割引なし」。Moonshotは「標準の60%」で、50%減より浅い設定です。
  • Batchとキャッシュは併用できる。Anthropicは公式に「Batch API and prompt caching discounts can be combined.」と明記しています。同じ前置きを何度も流す夜間バッチなら、キャッシュ＋Batchの二段構えが最も安くなります。

たとえば問い合わせログ20万件を、夜間に「問い合わせ種別」へ分類する処理を考えます。1件あたり入力1,500トークン・出力200トークンとすると、合計は入力3億トークン・出力4,000万トークンです。

Kimi K3.1 Pro（$2.00／$10.00）$600 + $400 = $1,000$600（標準の60%）−$400

この処理は翌朝までに結果が揃っていればよいので、Batchの締切（多くは24時間以内）に収まります。逆に、ユーザーの投稿をその場で判定して画面に返す用途は、24時間待てないためBatchに向きません。「日次で回る集計・分類・抽出・埋め込み生成」はBatchの典型例で、「対話・エージェントのループ内」は通常APIのまま、という切り分けが実務的です。

なお、同じ前置き（分類の指示文やカテゴリ定義）を全件に付けるなら、プロンプトキャッシュと併用すると入力側がさらに下がります。Anthropicは併用可を明記しており、OpenAI・GoogleもキャッシュとBatchは別の割引軸として扱われています（併用時の適用順序は各社ドキュメントでご確認ください）。

Batchは「レイテンシと締切」のトレードオフ

Batch APIは非同期です。リクエストを投入するとジョブIDが返り、結果は後から取りに行く形になります。OpenAIは「Each batch completes within 24 hours (and often more quickly)」とし、完了ウィンドウは24時間のみ。Googleは「The target turnaround time is 24 hours, but in majority of cases, it is much quicker.」、xAIは「most completing within 24 hours」と書いています。公式に書かれているのは「24時間以内に完了する」という上限までで、「何時間で終わるか」は記載がありません。日中の業務に組み込むなら、前日夜に投入して翌朝回収する設計が安全です。

締切を過ぎたリクエストの扱いも会社ごとに違います。OpenAIは期限切れをエラーファイルに書き出し（batch_expired）、成功分だけを受け取る形になります。つまり「全件そろわない可能性」を前提に、再実行の設計を用意しておく必要があります。レート制限の扱いも別枠で、xAIは「Requests don't count towards rate limits」と明記しています。安くなる代わりに、締切・部分失敗・回収の運用を自分で持つのがBatchだと考えてください。

結果の保持期間は意外に短い。OpenAIは「The output file will automatically be deleted 30 days after the batch is complete.」と明記しています。結果はダウンロードしたら自分のストレージへ移すのが基本です。他社の保持期間は本ページの表では「未確認」としており、確認でき次第追記します。
