# Gemini（子育てママ）レビュー依頼テンプレ — 恒久手順

最終更新: 2026-11-21（okamo明示指示 OK-3 で観点3つを追加）

## いつ使うか
- **新しいLLMモデルを1件でも載せた日は必ず**、そのページ（ja/en）をレビューに出す。
- 特集ページ（/china-ai/ ・/mai/ など）の本文を並べ替え・追記した日も出す。
- 表の行を足した／年表に1行足した／見出しの年月を上げた、が対象。

## 依頼の出し方（ask_gemini_mother）
守ること:
- **1回の依頼で2ページまで**（ja/en で1セットと数える）。全ページ一括は禁止（入力トークン爆発）。
- 依頼文は下のテンプレをコピーし、`<PAGES>` と `<TODAY>` だけ差し替える。
- 画像（キービジュアル/OG）を見せる依頼と、本文の構成を見る依頼は**分ける**。
- Geminiは「読者（初心者）」の立場で見る。事実の正誤判定はGPT税理士と1次情報の役割。

## 依頼テンプレ（本文レビュー）

```
今日は <TODAY> です。次のページを「初めて読む人」の目で見て、問題点だけ箇条書きで返してください。
対象: <PAGES>（各ページのローカル実ファイルを file_read で読んでください）

見る観点（必須・毎回全部）:
(a) セクション分けの妥当性
    - 同じベンダー系列のモデルが別々のブロック/カードに散っていないか
    - 別系列（別会社）のモデルが同じブロック/カードに混ざっていないか
    - カードや節の見出しを見て「どの会社の話か」が即答できるか
(b) 年表・一覧の時系列順序
    - 末尾の年表・リリース一覧が**新しい順**（降順）になっているか
    - 途中に古い日付が1行だけ紛れていないか（先頭だけ新しくて以降が昇順、は典型的なNG）
    - 日付表記が混在していないか（2026-04-02 / 2026-05 / Nov 2026）
(c) 年月表記の鮮度
    - 「2026年◯月版」「最新モデル（2026年◯月）」「Latest models (◯ 2026)」が**今の月**か
    - 目次（TOC）の中の年月が本文の見出しと一致しているか（TOCだけ古い事故が起きやすい）
    - 本文中に「2026年10月」のような**古い月の断定**が残っていないか

返し方:
- 「ページ / 場所（見出し・行）/ 何が問題 / 直し方の案」の4点で。
- 問題が無い観点は「(a) OK」のように1行でよい。推測で埋めない。
```

## 依頼テンプレ（画像レビュー）

```
画像を1枚だけ見てください: <PATH or URL>
目的: <ページ名> のキービジュアル。
見てほしいこと: 文字化け・ラベル切れ・はみ出し・数値と日付が本文と一致しているか・
スマホ幅（375px相当）で読めるか。NGの場合は該当箇所を引用して返してください。
```

## 受けた後の扱い
- 「構成・順序・年月」の指摘は**台帳（facts.json）側を直して render**（HTML直接編集は戻る）。
- 目次（TOC）は台帳の外なので、ページHTMLを直接直す（renderで戻らない）。
- 軽微でも「欠落・入れ替わり・数値不整合」は公開前に実物で確認する（同一性で確認。grep -c は水増しされる）。
