一次情報に基づく対応可否（2026-09-06確認）。この表はAPIへバイナリを直接渡せる形式だけを載せます（確実にOKなもののみ）。ツールでテキスト化して渡す方式はどのモデルでも可能なので非掲載です。Qwen3.8-Flashは公式が画像・動画理解を明記しているのでアイコンを出しています。音声・PDF・Officeの直読みは同ページで確認できないため非表示。ClaudeのPDFは公式の視覚理解なので掲載、DOCX/XLSXは事前変換が必要なので非表示。

注記の意味

  • Gemini の DOCX / XLSX / PPTX = テキスト抽出。公式 Document understanding は PDFだけ視覚理解（レイアウト・チャート・表を画像として見る）。Word / Excel / PowerPoint はテキストを抜き出して渡す扱いで、PDFと同じ視覚解析ではない。ファイルを送れても「PDF相当」ではない。
  • GPT-6 Astra / GPT-5.6 Sol / Luna の画像出力 = ツール経由。公式モデルページの本体出力はテキスト。画像を出すには Responses API の image generation tool（GPT-Image 2.0） を別途呼ぶ。モデルがピクセルを直接返すわけではない。
  • GLM 5.3 Flash の PDF / Office は非掲載。公式 How to Use が明示するネイティブ入力は image_url（画像）と動画。Input Modality の File や Office成果物は「ツールを呼んで文書を処理・作成する」作業で、バイナリ直読みではない。テキスト化ツールを渡せば他モデルでも同じなので、この表では非対応とする。

モダリティ別の課金ルール全モデル共通の注意点

同じ「1M tokens」でも、モダリティによって単価が変わる・トークン換算される、というのが最大の落とし穴。主要ポイントをまとめます。

① 画像・動画・PDFは「トークン換算」される。Geminiでは画像・動画・PDFは標準入力単価でトークン換算、PDF（DOCUMENTモダリティ）は画像トークン単価で課金。動画が長いと入力トークンが膨らむが、モデルが実際に処理した入力トークンとして課金されます。動画は再生時間の長さと単純に比例するわけではなく、モデルがサンプリングした映像・音声などの処理量に応じて入力トークン数が変わるため、同じ長さでも内容や設定によって料金が変わります（Googleの video understanding では長尺動画の入力トークンを実際の再生時間ベースより最大約88%削減できる仕組みがあります）。
② 音声入力はモデルにより「2倍課金」される。Gemini 3.1 Flash-Lite（$0.25→音声 $0.50）、Gemini 3 Flash（$0.50→$1.00）、Gemini 2.5 Flash（$0.30→$1.00）、2.5 Flash-Lite（$0.10→$0.30）のように音声だけがテキスト等の2〜3倍。一方 Gemini 3.5 Flash-Lite・3.6/3.7/3.8 Flash は音声も標準単価と同額（3.8公式料金表はモダリティ別の区分を設けず一律）。音声入力の単価はモデルごとに異なり、すべてのGeminiモデルに共通する仕様ではありません。音声中心のワークロードはモデル選定が肝心。
③ Gemini 3.8/3.7/3.6 Flash の初回価格（$0.75/$3.75）は2026-12-31まで。2027-01-01以降は $1.50/$7.50 へ倍額化。画像・音声・動画入力も含めてこの標準単価で課金。予算は標準価格ベースで設計を。
④ ライブ（リアルタイム）・画像生成・音声生成（TTS）はコアモデルとは別モデル。下のセクション参照。コアLLMは「入力は多モダリティ、出力はテキスト」が現在の主流で、テキスト以外を出力するには専用モデルを使う。

「この入力・出力をしたい」ときのモデル選び

マルチモーダルが絡む典型的なパターンで、どのモデルを選べばいいかを一言で。

画像を「理解」して回答
ほぼ全モデル対応。コスパなら Qwen3.8-Flash・GLM 5.3 Flash、品質なら GPT-6 Astra
音声（会話）を入力したい
Gemini 3.8/3.7 Flash が音声入力を標準単価で受ける。音声中心なら 3.1 Flash-Lite は2倍課金に注意
動画を理解して要約・分析
Gemini 3.8 Flash（動画+音声対応）。Qwen3.8-Flashも公式に Non-Real-Time Video Understanding を記載（音声入力は非対応）。
Office文書（PDF/PPTX/DOCX/XLSX）を扱う
バイナリ直読みできるのは GeminiのPDF（視覚）と ClaudeのPDF。DOCX/XLSX/PPTX はGeminiでもテキスト抽出。GLMのOfficeはツール経由なので他モデルと同列に置かない。
