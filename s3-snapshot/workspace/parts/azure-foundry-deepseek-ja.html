Azure AI Foundry で動かす（DeepSeek-V4-Flash-0731）

DeepSeek 自社 API だけでなく、Microsoft Azure の Azure AI Foundry（Microsoft Foundry） 経由でも DeepSeek 系モデルをデプロイできます。 ここでは Azure が「Direct from Azure」として販売している DeepSeek-V4-Flash-0731 を、Azure CLI でデプロイして curl で疎通確認するまでの手順を示します。

ℹ️ DeepSeek-V4-Flash-0731 と V4.1 Flash の関係: -0731 は V4.1 Flash のひとつ前の世代（2026-07-31 リリース・V4-Flash-Preview と同じアーキテクチャ／サイズで再事後学習したもの）です。 DeepSeek 自社 API では V4 Flash 系は退役して V4.1 Flash に統合されましたが、Azure AI Foundry では DeepSeek-V4-Flash-0731 が現在も Preview モデルとして提供されています（2026-09-13 時点）。 Azure 側の仕様は Microsoft Learn の記載に基づきます。コマンド列の流れは運営者（okamoちゃんねる）が 2026年9月時点で動作確認済みのものです。

前提

  • Azure サブスクリプション（リソースを作成できる権限があること。リソースプロバイダー登録には Owner 権限が必要です）
  • Azure CLI（az）。az cognitiveservices 系コマンドは core に同梱されているため、Azure CLI 2.60 以降であれば追加拡張は不要です
  • az login で対象サブスクリプションにログイン済みであること

使うプレースホルダ

コマンド内のプレースホルダ一覧
プレースホルダ意味・指定する値
<SUBSCRIPTION_ID_OR_NAME>使う Azure サブスクリプションの ID または名前
<RESOURCE_GROUP>リソースグループ名（例: rg-deepseek）
<LOCATION>リージョン（例: eastus）。モデルによって提供リージョンが異なるため、Azure ポータルのモデルカタログで確認してください
<ACCOUNT_NAME>Azure AI Services アカウント名。全世界で一意にする必要があります（例: dsflash0731）。--custom-domain にも同じ値を使います
<DEPLOYMENT_NAME>デプロイ名（任意）。API 呼び出しの model に指定するのはモデル名ではなく、このデプロイ名です（例: deepseek-0731）
<MODEL_VERSION>モデルのバージョン文字列。実値は次の az cognitiveservices account list-models で確認してください（本ページでは断定しません）
<API_KEY>Azure AI Services アカウントのキー（手順内で CLI から取得します）

STEP 0 — Azure CLI の準備とリソースプロバイダー登録

最初にこれを済ませておくと、後の手順で MissingSubscriptionRegistration エラーに当たりません。

# Azure CLI のバージョン確認（2.60 以降を推奨）
az version

# 未ログインならログイン
az login

# 使うサブスクリプションを選択
az account set --subscription "<SUBSCRIPTION_ID_OR_NAME>"

# リソースプロバイダーを登録（MissingSubscriptionRegistration 対策）
az provider register --namespace Microsoft.CognitiveServices

# 登録状態を確認（Succeeded になるまで数分かかることがあります）
az provider show --namespace Microsoft.CognitiveServices --query registrationState -o tsv

STEP 1 — リソースグループを作成

az group create \
  --name "<RESOURCE_GROUP>" \
  --location "<LOCATION>"

STEP 2 — Azure AI Services アカウントを作成

--custom-domain を指定すると、以降のエンドポイントが https://<ACCOUNT_NAME>.openai.azure.com/ の形式になります。

az cognitiveservices account create \
  --name "<ACCOUNT_NAME>" \
  --resource-group "<RESOURCE_GROUP>" \
  --kind AIServices \
  --sku S0 \
  --location "<LOCATION>" \
  --custom-domain "<ACCOUNT_NAME>" \
  --assign-identity \
  --allow-project-management true \
  --yes

STEP 3 — DeepSeek-V4-Flash-0731 をデプロイ

まず利用可能なモデルとバージョンを確認し、その値でデプロイします。

# デプロイ可能な DeepSeek 系モデルとバージョンを確認
az cognitiveservices account list-models \
  -n "<ACCOUNT_NAME>" -g "<RESOURCE_GROUP>" \
  --query "[?contains(name,'DeepSeek')].{name:name,format:format,version:version}" -o table

# モデルをデプロイ（SKU は GlobalStandard、容量は 1 から開始）
az cognitiveservices account deployment create \
  --name "<ACCOUNT_NAME>" \
  --resource-group "<RESOURCE_GROUP>" \
  --deployment-name "<DEPLOYMENT_NAME>" \
  --model-name "DeepSeek-V4-Flash-0731" \
  --model-version "<MODEL_VERSION>" \
  --model-format "DeepSeek" \
  --sku-name "GlobalStandard" \
  --sku-capacity 1

💡 --sku-capacity はクォータ（Tokens Per Minute、千トークン単位）として消費されます。容量が足りないと InsufficientQuota でデプロイに失敗することがあるため、その場合は値を調整するか、Azure ポータルでクォータの増加を申請してください。

STEP 4 — 接続情報を環境変数に入れる

# エンドポイント（OpenAI 互換）と API キーを取得
export AZURE_AI_ENDPOINT="https://<ACCOUNT_NAME>.openai.azure.com/openai/v1/"
export AZURE_AI_API_KEY="$(az cognitiveservices account keys list \
  --name "<ACCOUNT_NAME>" \
  --resource-group "<RESOURCE_GROUP>" \
  --query key1 -o tsv)"

# API 呼び出しの model に入れるのはデプロイ名
export DEPLOYMENT_NAME="<DEPLOYMENT_NAME>"

STEP 5 — curl で疎通確認

curl -sS "$AZURE_AI_ENDPOINT/chat/completions" \
  -H "Content-Type: application/json" \
  -H "api-key: $AZURE_AI_API_KEY" \
  -X POST \
  -d '{
    "model": "'"$DEPLOYMENT_NAME"'",
    "messages": [
      { "role": "user", "content": "Reply with just OK." }
    ]
  }'

✅ 応答 JSON が返れば疎通完了です。model にデプロイ名を渡している点に注意してください（モデル名 DeepSeek-V4-Flash-0731 を渡すと 404 などになることがあります）。 環境変数にキーを置きたくない場合は -H "api-key: <API_KEY>" を直接指定します。 Entra ID（旧 Azure AD）で認証する場合は、公式チュートリアルにあるとおり DefaultAzureCredential 等でスコープ https://ai.azure.com/.default のトークンを取得する方式も使えます。

⚠️ MissingSubscriptionRegistration が出たら

次のようなエラーです（HTTP 409 / Conflict）。サブスクリプションで Microsoft.CognitiveServices リソースプロバイダーが未登録なだけなので、リソース作成側の問題ではありません。

MissingSubscriptionRegistration
The subscription is not registered to use namespace 'Microsoft.CognitiveServices'.
  • 対処1（CLI）: az provider register --namespace Microsoft.CognitiveServices を実行し、az provider show --namespace Microsoft.CognitiveServices --query registrationState -o tsv が Registered になるまで待ちます（数分かかることがあります）。
  • 対処2（ポータル）: Azure ポータル →「サブスクリプション」→「リソースプロバイダー」→ Microsoft.CognitiveServices を選び「登録」。
  • 権限: 登録にはサブスクリプションの Owner 権限が必要です。権限が無い場合は管理者に依頼してください。
  • 公式のトラブルシューティング: Register a resource provider
