Run it on Azure AI Foundry (DeepSeek-V4-Flash-0731)

Beyond DeepSeek's own API, you can deploy DeepSeek models through Microsoft Azure's Azure AI Foundry (Microsoft Foundry). This walkthrough deploys DeepSeek-V4-Flash-0731, which Azure sells as a "Direct from Azure" model, using the Azure CLI, then verifies the endpoint with curl.

ℹ️ How DeepSeek-V4-Flash-0731 relates to V4.1 Flash: -0731 is the previous generation (released 2026-07-31; same architecture and size as V4-Flash-Preview, re-post-trained). On DeepSeek's own API the V4 Flash generation was retired into V4.1 Flash, but Azure AI Foundry still offers DeepSeek-V4-Flash-0731 as a Preview model (as of 2026-09-13). The Azure-side details come from Microsoft Learn. The command sequence was verified in practice by the operator (okamo channel) in September 2026.

Prerequisites

  • An Azure subscription with permission to create resources. Registering a resource provider requires Owner at the subscription level.
  • The Azure CLI (az). The az cognitiveservices commands ship in the CLI core, so no extra extension is needed on Azure CLI 2.60 or later.
  • You are signed in to the target subscription via az login.

Placeholders used below

Placeholders used in the commands
PlaceholderWhat to supply
<SUBSCRIPTION_ID_OR_NAME>The ID or name of the Azure subscription to use
<RESOURCE_GROUP>Resource group name (for example rg-deepseek)
<LOCATION>Region (for example eastus). Availability differs per model — check the model catalog in the Azure portal
<ACCOUNT_NAME>Azure AI Services account name. Must be globally unique (for example dsflash0731). The same value is reused for --custom-domain
<DEPLOYMENT_NAME>Deployment name (your choice). The model field in API calls takes the deployment name, not the model name (for example deepseek-0731)
<MODEL_VERSION>The model version string. Read the actual value from the az cognitiveservices account list-models call below — this page does not assert it
<API_KEY>The Azure AI Services account key (fetched from the CLI in the steps below)

Step 0 — Prepare the Azure CLI and register the resource provider

Doing this first avoids the MissingSubscriptionRegistration error later on.

# Check the Azure CLI version (2.60 or later recommended)
az version

# Sign in if needed
az login

# Select the target subscription
az account set --subscription "<SUBSCRIPTION_ID_OR_NAME>"

# Register the resource provider (prevents MissingSubscriptionRegistration)
az provider register --namespace Microsoft.CognitiveServices

# Check registration state (may take a few minutes to reach Succeeded)
az provider show --namespace Microsoft.CognitiveServices --query registrationState -o tsv

Step 1 — Create a resource group

az group create \
  --name "<RESOURCE_GROUP>" \
  --location "<LOCATION>"

Step 2 — Create the Azure AI Services account

Passing --custom-domain makes later endpoints take the form https://<ACCOUNT_NAME>.openai.azure.com/.

az cognitiveservices account create \
  --name "<ACCOUNT_NAME>" \
  --resource-group "<RESOURCE_GROUP>" \
  --kind AIServices \
  --sku S0 \
  --location "<LOCATION>" \
  --custom-domain "<ACCOUNT_NAME>" \
  --assign-identity \
  --allow-project-management true \
  --yes

Step 3 — Deploy DeepSeek-V4-Flash-0731

First list the available models and versions, then deploy with those values.

# List deployable DeepSeek models and their versions
az cognitiveservices account list-models \
  -n "<ACCOUNT_NAME>" -g "<RESOURCE_GROUP>" \
  --query "[?contains(name,'DeepSeek')].{name:name,format:format,version:version}" -o table

# Deploy the model (GlobalStandard SKU, starting capacity 1)
az cognitiveservices account deployment create \
  --name "<ACCOUNT_NAME>" \
  --resource-group "<RESOURCE_GROUP>" \
  --deployment-name "<DEPLOYMENT_NAME>" \
  --model-name "DeepSeek-V4-Flash-0731" \
  --model-version "<MODEL_VERSION>" \
  --model-format "DeepSeek" \
  --sku-name "GlobalStandard" \
  --sku-capacity 1

💡 --sku-capacity consumes quota measured in Tokens Per Minute (thousands). If capacity is insufficient the deployment can fail with InsufficientQuota — adjust the value, or request a quota increase in the Azure portal.

Step 4 — Export the connection settings

# Endpoint (OpenAI-compatible) and API key
export AZURE_AI_ENDPOINT="https://<ACCOUNT_NAME>.openai.azure.com/openai/v1/"
export AZURE_AI_API_KEY="$(az cognitiveservices account keys list \
  --name "<ACCOUNT_NAME>" \
  --resource-group "<RESOURCE_GROUP>" \
  --query key1 -o tsv)"

# The API "model" field takes the deployment name
export DEPLOYMENT_NAME="<DEPLOYMENT_NAME>"

Step 5 — Verify connectivity with curl

curl -sS "$AZURE_AI_ENDPOINT/chat/completions" \
  -H "Content-Type: application/json" \
  -H "api-key: $AZURE_AI_API_KEY" \
  -X POST \
  -d '{
    "model": "'"$DEPLOYMENT_NAME"'",
    "messages": [
      { "role": "user", "content": "Reply with just OK." }
    ]
  }'

✅ A JSON response means the endpoint is live. Note that model must be the deployment name — passing the model name DeepSeek-V4-Flash-0731 can return a 404. If you would rather not export the key, use -H "api-key: <API_KEY>" inline. For Entra ID (formerly Azure AD) authentication, Microsoft's tutorial shows obtaining a token with scope https://ai.azure.com/.default via DefaultAzureCredential.

⚠️ If you hit MissingSubscriptionRegistration

It looks like this (HTTP 409 / Conflict). It simply means the Microsoft.CognitiveServices resource provider is not registered on the subscription — nothing is wrong with your resource request.

MissingSubscriptionRegistration
The subscription is not registered to use namespace 'Microsoft.CognitiveServices'.
  • Fix 1 (CLI): run az provider register --namespace Microsoft.CognitiveServices and wait until az provider show --namespace Microsoft.CognitiveServices --query registrationState -o tsv reports Registered (this can take a few minutes).
  • Fix 2 (portal): Azure portal → Subscriptions → Resource providers → select Microsoft.CognitiveServices → Register.
  • Permissions: registration requires Owner on the subscription. Ask an administrator if you lack it.
  • Official troubleshooting: Register a resource provider
