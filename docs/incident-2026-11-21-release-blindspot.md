## 何が起きていたか

| # | 指摘 | 実際に起きていたこと |
|---|---|---|
| 1 | 新モデル（GPT-6.2 Sol / Astra）に全く気づいていない。致命的 | 当日のランは OpenAI の料金ページを**一度も取得していない**。代わりに台帳を走査して「直近21日の漏れ 0件」と日報に書いた |
| 2 | 古いモデルを更新している（Claude Mythos 5.1 提供開始 / GPT-5.6 Sol 公開） | 台帳に `released` の空のスタブがあり、そこへ**ページの `datePublished` をリリース日として代入**した。その結果、年表に「GPT-5.6 Sol 公開 2026-08-29」という**存在しないリリース**が入った（実際は 2026-07-09 の GPT-5.6 ファミリー）。Mythos 5.1 は既存の「Claude Fable 5.1 / Mythos 5.1 公開」と同じ 2026-09-01 に**二重掲載**された |
| 3 | `/china-ai/` の「MiniMax が Kimi と同じブロック」を、MiniMax だけの独立セクション新設で直した | 依頼は**カードの所属**（`lab-grid` の中の1枚）の修正。実際には台帳に `minimax-h` ブロックを新設し、HTML に `<section>` と目次項目を追加した。カード数 8→7・セクション数 7→8 |

## 原因

### 1. 新モデルの検知が「台帳の自己参照」だった（#1）

`main.py` の `_propose_themes()` の A0 は、**台帳 `facts.json` の `models` を走査して**
「直近21日で単価が無い／料金比較・計算機・年表に未掲載」を挙げていた。

```
for k, v in models.items():        # ← 台帳に無いモデルは絶対に候補にならない
```

台帳が古ければ「漏れ 0件」という**偽の緑**になる。実際、11-21 の日報は
「新モデルの漏れ 0件（載っていない新モデルは無い）」と書いた。
`page_audit` の R10/R11 も `_recent_models()` が台帳基準なので同じ穴を持つ。
一次情報（各社の公式料金ページ）を**毎回読む工程が存在しなかった**。

### 2. 「リリース日」の出どころが無かった（#2）

台帳のスキーマに `released` はあるが**出典の項目が無く**、埋まっていないモデルは
エンジニアが「ページの `datePublished`」で埋めた（当日のログに
`released = page datePublished` と明記されている）。ページの作成日はリリース日では
ないため、年表に誤った日付が入る。既存のゲートは**表**（R3/R8）を見るが、
**年表のカード**は見ていなかったので、二重掲載も捏造日付も素通りした。

### 3. 「直す」の単位が指示と一致していなかった（#3）

- 指示の粒度が「MiniMax の**ブロック見出し**を逐語で報告」であり、実行者は
  「見出し＝h2 セクション」と解釈した
- 台帳の編集インタフェースが `features.<slug>.blocks[]`（= h2 単位）しか無く、
  「同じ h2 の中のカードを動かす」という操作に名前が無い
- 検証が「MiniMax の見出しがあること」になっていて、**構造の不変条件**
  （カード数・セクション数）を見ていなかった

結果として「不具合の**再現条件**」ではなく「不具合の**見た目**」を直した。

## いまの設計

### 1. 公式ソースの見張り（`tools/watch_releases.py`・コードで実行）

毎ランの開始時に、**台帳ではなく各社の公式料金ページ**を取得し、モデルIDを抽出して
台帳と突き合わせる。

| ソース | 抽出 |
|---|---|
| `developers.openai.com/api/docs/pricing` | `gpt-*` |
| `platform.claude.com/docs/en/about-claude/pricing` | `claude-(opus\|sonnet\|haiku\|fable\|mythos)-*` |
| `ai.google.dev/gemini-api/docs/pricing` | `gemini-*` |
| `api-docs.deepseek.com/quick_start/pricing` | `deepseek-*` |

- 候補は**系統ごとの最大版より新しいID**を優先（旧モデルで埋もれさせない）。
  最初の実装は旧モデル12件で枠が埋まり、**GPT-6.2 が候補から漏れた**ので、
  版番号で並べ替える方式に直した（回帰テストで固定）
- 同じ版の別バリアントは**初出の1回だけ**出す（毎日ノイズを出さない）
- 結果は `data/release_watch.json` に残し、ミッションの**先頭**に差し込む
- **取得に失敗したソースは「新モデル無し」ではなく「不明」**として日報に書かせる
  （11-15 の鮮度キューが2ラン連続0件だった「静かな偽OK」を繰り返さない）

### 2. 年表のカードを検査する（`page_audit.py`・R12〜R14）

| コード | 見るもの | 今日の事象 |
|---|---|---|
| R12 | 同じ日に、語の重なりが50%以上のカードが2件 | Mythos 5.1 の二重掲載を検出 |
| R13 | カードの id がモデルidと一致するとき、カードの日付 ≠ 台帳の `released` | 「GPT-5.6 Sol 公開 08-29」を検出 |
| R14 | 台帳の `released_source` が `page-published` / `unknown` なのに年表に出している | 出典なしの日付を止める |

「発表 / 予告」を含むカードは R13 の対象外（GA と発表で日付が違うのは正常）。
R12〜R14 は**既存の借金でも公開を止める**（事実の誤りを出し続ける方が高くつく）。
あわせて R11 の誤検知を除去した（更新履歴の節は本文ではない）。

### 3. 構造の後退を止める（`tools.py` の公開ゲート）

既存ページの上書き公開で、**`class="section-title"` が増えた／`class="lab-card"` が
減った**らアップロードを拒否する。意図して増やす場合は
`data/structure_allow.json` に `{"china-ai/index.html": {"sections": 8}}` のように
**意図を書いて**許可する（黙って通す道は作らない）。

### 4. プロンプト（`prompts.py` の `SITE_RULES`）

- 「漏れ0件」を台帳で判断しない。公式ソースの見張りの候補が最優先。失敗は「不明」
- 年表は「起きた日」に1件だけ。同じ出来事を言い換えて足さない
- `released` は**公式発表の日付のみ**。分からなければ空＋`released_source: unknown`
  で年表に出さない（`official-announcement` / `page-published` / `unknown` を必ず添える）
- 不具合は**指摘された範囲**だけ直す。セクションを増やすのは内容が増えたときだけ

## 残る穴（次に効く順）

1. **見張りの対象は4社の料金ページだけ**。xAI（`x.ai/api` は 403）・Meta・Zhipu・
   Moonshot・Xiaomi は未対応。RSS/チェンジログの取得を足す余地がある
2. **R12 の閾値は語の重なり50%**。日本語の言い換えが大きい二重掲載は取り逃す
   （例:「提供開始」と「リリース」で語が揃わない場合）
3. **`released_source` は既存モデルに未設定**。新規・修正分から必須にしており、
   過去分は空のまま（R14 は明示的に `page-published` / `unknown` のときだけ鳴る）
4. **構造ゲートは「増えた／減った」だけ**。同じ枚数で中身を入れ替える誤りは見ていない

## 前提が変わったときの要注意事項

| 前提 | 崩れた場合に設計が変わる点 |
|---|---|
| 各社の公式料金ページにモデルIDが載る | 載らないモデル（限定提供・法務向け構成など）は見張りに出ない。発表ブログ/RSS を足す必要がある |
| 年表のカードの `id` がモデルidと一致する | 一致しない命名にすると R13 が効かなくなる（`tl-<model>-<event>` のような命名にするなら R13 も対応が要る） |
| 1ページ1つの `lab-grid` | 複数グリッドを持つページでは「カード減」の判定が粗くなる（グリッド単位の比較に変える） |
| 公開は `site_upload` 経由 | 手動の `aws s3 cp` はゲートを通らない（今回の修正も最後はパイプラインと同じ手順で公開した） |
