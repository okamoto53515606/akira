## 何が起きていたか

### 1. キービジュアル（OGカード）だけが古い

`/china-ai/` の本文は 2026-11-14 に更新されていたが、先頭の大きな画像
（`/assets/og/ja-china-ai.png`）には **2026-10-29** の日付と
**「Qwen 4 は公式『学習中』、時期は未公表」** が焼き込まれたままだった。
本文は「11/11 からプレビュー提供中」と書いており、**同じ画面で矛盾**していた。

原因は、画像の文面が生成スクリプト
`workspace/parts/og/make_og_2026-10-29.py` の **文字列リテラルに直書き**されていて、
本文（HTML）と機械的につながっていないこと。日付も `'2026-10-29'` の固定値だった。

### 2. 目次と本文の間に余白が無い

`/china-ai/` の目次（`.toc`）の直後のセクションが `padding-top:0` で、
`.toc` 側に下余白が無かったため、**枠線と見出しが接していた**。
同じ書き方（目次＋`padding-top:0`）のページは全86ページ中 **30ページ** あった。

### 3. 追記の寄せ集めで「結局いまどうなのか」が分からない

`/deepseek-v4-1-flash/` は、9月のリリース時点の情報（ベンチマーク表・
「2026-09-13 時点」の見出し・`取得日: 2026-10-05`）と、10-17 の更新情報
（`V4.1-Flash-1017`・Web検索/Fetch API）が**同じページに併存**していた。

- 冒頭に「2026-11-12 追記:」のバナーが差し込まれ、本文の H1 より上に出ていた
- ベンチマークが **2系統**（2026-09-10 の表と 2026-10-17 の箇条書き）あり、
  同じ指標に違う値が並んでいた（例: `Terminal-Bench 4.0` 31.2 と 42.3）
- 「最終更新 2026-11-12」「取得日 2026-10-05」「2026-09-13 時点」が同居
- しかも冒頭バナーは **「Azure のカタログも 1017」** と書いていたが、
  実際のカタログは **Version 2026-09-10 のまま**（2026-11-17 実測）。事実誤りでもあった
- `/en/china-ai/` は H1 が `[September 2026]`、JSON-LD の headline も `Sep 2026` のまま
  `dateModified` だけ 11-14 だった

**どのゲートも止めなかった**理由: 既存の検査は「リンク・meta・表の列数・日付の四点」を見るが、
**同じページ内の新旧の併存**と**画像の中の文字**は対象外だった。

## 再発防止（実装済み）

1. **`page_audit.py`（8本目のゲート群）** — 決定論的・LLMコスト0
   - R1 `dateModified` と「最終更新」表示の不一致
   - R2 `2026-11-12 追記:` / `Added 2026-11-12:` の**追記バナー**
   - R3 同じ見出し構成の表で、同じ行ラベルに違う値
   - R4 見出しの年月が `dateModified` より古い（`[September 2026]` の類）
   - R5 **キービジュアルの生成日が本文の最終更新より古い**
   - R6 **日付で始まる見出し**（「2026-10-17 の更新 — …」＝更新を積む節）
   - R7 「取得日」が最終更新より30日以上古い（WARN）
   - R8 **同じ指標に2つの値**（表と箇条書きの併存。`w/o tools` と `w/ tools` は別指標）
2. **優先度つきの監査義務（okamo案）** — `data/page_priority.json` の score 順に、
   **上位5ページは7日以内・それ以外は21日以内**に1回監査する。
   対象の選定は `main.py` がミッション作成時に**コードで**行い（`page_audit.mission_line`）、
   プロンプトに「今日の必須監査」として差し込む。実施したかは後処理
   （`page_audit.verify_assigned`）が検算して日報の「自動メンテナンス」に載せる
   （LLMの「やりました」を信用しない）。
   score の元は GA4 のPVと GSC のクリックで、Akira が `set_page_priority` で更新する
   （未更新でも既定順で動く）。
3. **キービジュアルを台帳化** — `data/og_specs.json` が文面の正。`og_card.py` が描画と
   同時に `generated` を更新する。画像は機械が読めないので、**Gemini の目**も使う。
4. **プロンプト**（`prompts.py`）
   - エンジニア: 「更新の書き方（追記しない）」「同じ指標の新旧を並べない」
     「日付を1つに揃える」「キービジュアルも本文の一部」
   - Gemini: **S10「キービジュアルの日付・モデル名・数値が本文と一致しているか」**
   - GPT: 「新旧の混在」を**クリティカル**扱い
   - `SITE_RULES`（Akira/全員）にも同じ原則を追記
5. **回帰テスト** — 修正前のページ（S3バージョニングから取得）を食わせて
   R2/R4/R5/R6/R8 が出ること、修正後は 0 件であることを確認（21項目）。
   配線・OGカード生成のテストは別途9項目。
