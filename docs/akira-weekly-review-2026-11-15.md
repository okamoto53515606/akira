## 4. 今後やりたいこと

### 4.1 【核1】Fargate Akira の自己改善ループ — 自律的に改善できる状態にする

**目的（忘れない）**: 役に立つサイトを作り、PV を増やす。

**現状**: 描画・ゲート・候補抽出・鮮度取得は**コード**で回るようになった。ここが今日の最大の前進。
一方で「うまくいかなかったことを翌週に活かす」部分はまだ弱い。

| 足りないもの | なぜ効くか | 規模 |
|---|---|---|
| **判断ログ** | 「なぜその変更をしたか」が残らず、翌日同じ判断をやり直している（為替の質問がその実例） | 中 |
| **失敗の自動還元** | ゲートが止めた理由は `lessons` に自動記録する仕組みがあるが、**プロンプト側に昇格させる経路が無い**（同じ失敗が月単位で再発する） | 中 |
| **未判定の自動判定** | §3 の判定を**人が見に行っている**。期日が来たら機械が判定し、落ちたら `site_plan` に差し戻すべき | 小 |
| **公開前リハーサル** | 変更 → 描画 → ゲート → 戻せるか、を1コマンドで確認できない | 小 |

**目標状態**: okamo が何も言わなくても、毎ラン「新モデル調査 → 掲載 → ゲート → 公開 → 日報」が回り、
okamo は**例外（＝okamo にしか決められないこと）だけ**を見る。

### 4.2 【核2】公開サイトの品質向上

品質の内訳と、いまの担保方法:

| 品質の内訳 | いまの担保 | 残っている穴 |
|---|---|---|
| 情報が古い | 鮮度キュー（コードが取得）＋ `check_facts_consistency` | 新モデルの**未掲載**（今日、候補1番に入れた） |
| 重複 | `check_site_integrity` の page-dup | 同一事実が複数ページで別方向に書かれる型は未検出 |
| レイアウトずれ | `box-width` / `container-escape` / `check_css_contract`（CSSの必須プロパティ） | 実画面の見た目は Gemini の S1〜S8 とスクショ依存 |
| 説明が長い | `long-text` / 目次の自動生成 | 3,000字制限は用語集では不可能と判断し目次で解決 |
| わかりにくい | Gemini S1〜S8（**実画面のスクショ必須**） | 観測が主観的。GA4 のエンゲージメントと結びついていない |
| 間違い | GPT税理士（**引用が無い critical は機械的に降格**） | レビュー担当の証拠が古い cache にならないよう当日分のみ渡す |

- **T55** ヒーロー画像を全ページに広げるか決める（用語集・個別モデルページは未適用）
- **T56** 「色の変化」の機械判定を強める（今は「10行以上の表＋色分け0」だけ）
- **T63** 画像生成スクリプト6本を `_font.get_font()` に寄せる（書体を1箇所で差し替えられるように）

**目標**: **同じ失敗を2回しない**。失敗したら①ゲートに1行足す ②観点が無いなら Gemini のチェックリストに1行足す、のどちらかで必ず捕捉する。

### この1件から出た原則（§4 の核に足す）

- **時刻で突き合わせる検査は、書く側と読む側が同じ時計を使っているかを見る**。
  11-26 は「`last_run` を上書きしていた」で直したが、**日付そのものが食い違って
  いれば merge しても一致しない**。嘘の原因が2段あった。
- **公開経路を増やしたら、その経路が既存の防御を通るかを1行ずつ確かめる**。
  経路が4本あればゲートも4本要る。1本化できるなら1本にする。
- **決定はデータとゲートに書く**。文章（lessons / site_plan）は次の描画で上書き
  されることがある（`write_back_shown_on` が実例）。
- **意味のない警告を出し続けない**。ノイズは本物の異常を隠す。
