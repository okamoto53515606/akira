# 2026-11-27 配布元カタログの版ずれ（Azure）と、監査・証拠・計算機の「静かな緑」

## 1. 事象（3件）

### (1) Azure のカタログ版が古いまま公開され続けていた

`/deepseek-v4-1-flash/` と `/en/deepseek-v4-1-flash/` は次のように書いていた
（2026-11-17 に確認した内容）。

- モデルカタログ: `DeepSeek-V4.1-Flash` / Version `2026-09-10`（Preview）
- **版が本家より古い**: カタログの版は `2026-09-10` のまま。新しい版を前提にしないでください

実際には 2026-11-17 の時点で、Azure は `DeepSeek-V4.1-Flash-1017`
（Version `2026-10-17` / Preview / 1000k context / 128k output / Input type: text）を
**別エントリとして追加**していた。

```
https://ai.azure.com/catalog/models/DeepSeek-V4.1-Flash        -> Version 2026-09-10
https://ai.azure.com/catalog/models/DeepSeek-V4.1-Flash-1017   -> Version 2026-10-17
```

既存エントリの版が上がるのではなく**名前ごと増える**ので、「カタログの版は
2026-09-10 のまま」という記述は静かに嘘になった。台帳にもページにも「古くなった」
とは書かれないため、11-26 のランまで誰も気づけなかった（課題162 は
`en/deepseek-v4-pro` の取得日が 2026-09-13 で止まっている、という形で残っていた）。

### (2) 日報が「ページ監査: 未実施 2件」と嘘をついた

11-26 の日報の自動メンテナンス欄は

```
ページ監査: 未実施 2件（/image-api-pricing/, /en/deepseek-v4-pro/）
```

と書いたが、Akira は両ページを監査して ERROR 0 を確認している。
`page_audit.audit_pages` が状態の `last_run` を**呼び出しごとに上書き**していたため、
1日に複数回（ページを分けて、または直したあとの再確認で）呼ぶと
**最後の1回のページしか残らなかった**。

### (3) GPT税理士に渡す一次情報が、名前順6件で打ち切られていた

11-26 は当日取得の cache が12件あった。`_evidence_block` はファイル名の
アルファベット順に6件で打ち切っていたので、先頭6件が
`deepseek-*` / `kimi-*` / `openai-for-healthcare` / `openai-healthcare-announcement` /
`openai-models-docs` で埋まり、**`openai-pricing` と `zai-*`（4件）が丸ごと落ちた**。

GPT税理士は「提示資料の範囲外」「一次情報が無い」と書き、Akira は
「中身はあるのに渡っていない（課題188）」と記録した。中身はあった。

同じ日、`/tmp/site/data/models.json` が61行・公開は59行という差（課題199）も
見つかったが、公開契約チェックは**公開中の現物しか見ない**ので緑のままだった。

---

## 2. 原因

| 事象 | 原因 |
|---|---|
| (1) | 「他社プラットフォームの掲載状況」を誰も定期的に見ていない。`watch_releases.py` は各社の料金ページから**新モデルID**は拾うが、配布元（Azure）の**版**は見ていない |
| (2) | `last_run` の意味が「直近の実行」になっていた。1日1回の想定で書かれていた |
| (3) | 「上限で落とす」ときに、**落としたことを伝えない**。並び順も依頼内容と無関係 |
| 課題199 | 契約が「公開中の現物」だけを対象にしていた。**描いたが公開していない**状態を見ていない |

いずれも共通する型は「静かな緑」——検査は走っているのに、対象外・上書き・打ち切りで
異常が見えない。

---

## 3. 対策

### (1) `platform_watch.py`（新規・機械が見張る）

- Azure のカタログ一覧（`?search=` クエリ）から **接尾辞つきのエントリも含めて**
  モデル名を拾い、各モデルページの `Version: <!-- -->YYYY-MM-DD`・提供段階・
  context・出力上限・入力種別を読む
- ページが書いている「カタログの版」（`Version <日付>`）と突き合わせ、
  **最新より古ければ stale**
- 結果はミッションに差し込み、stale があれば「今日の最優先」と明示。
  実行後にもう一度ローカルページだけを再判定し、**直っていなければ日報の
  自動メンテナンス欄に残す**（LLMの注意力に依存させない）
- 取得失敗は `unknown`＝「不明」。**「載っていない」とは書かない**
- 状態は `/workspace/data/platform_watch.json`（日をまたいで持ち越す）

対象は `TARGETS` テーブルで増やせる（ページのパスもここに書く）。

### (2) 監査の実施確認を当日累積に

`last_run` は**当日分をマージ**する（同じページは最後の結果で上書き）。
1日に何回 `audit_pages` を呼んでも、実施済みのページは消えない。

### (3) 一次情報の選び方を「依頼との一致」に

- 依頼文の英字語・URLホスト・モデルIDの断片（`z.ai` → `zai` も作る）で
  ファイル名を採点し、**関連する証拠を先に**入れる
- 上限は 6 → 10 件
- 打ち切ったファイル名を**明示**する（「一次情報が無い」と誤解させない）

### (4) ローカルと公開の計算機データの差（契約 C7）

`/tmp/site/data/models.json` と公開中の `data/models.json` の**モデル名の集合**を比較し、
ローカルにしか無いモデルがあれば違反として報告する（`publish_and_verify` で公開する）。
ローカルが無い（`site_download` 前）・公開が取れない場合は何も言わない。

### (5) favicon を `logo.svg` に統一

- `/favicon.svg` を `/logo.svg` と同じ図形・同じ色（teal `#14b8a6` の菱形＋
  濃紺 `#0b1220` の `L`・背景なし）にした
- iOS 用 `apple-touch-icon.png` は透過を許さないので、同じ座標を
  `report_assets/make_llm_touch_icon.py` が PIL で描く（背景 `#0b1220`）。
  **SVGを直したらこのスクリプトも直して再生成する**
- 97ページすべてが `/favicon.svg` と `/apple-touch-icon.png` を参照しているので、
  HTMLは触っていない（ファイル差し替えで全ページに効く）

## 4. 検証

- `test_regression_20261127.py` 32項目 ALL PASS（ネットワーク・AWS・LLMを使わない）。
  古いページHTMLを入力に **stale** 判定になること、取得失敗が `unknown` になること、
  1日に分けた監査で「未実施」と誤報しないこと（旧挙動では誤報することも確認）、
  当日12件の cache で `zai-*` が前置きに入り**打ち切りが明示される**こと、
  ローカル61行/公開59行の差を名指しで指摘することを確認
- 既存の回帰（11-19 / 11-21 / 11-22 / 11-24）は全て PASS
- 実ページ（Azure）に対して実行: 最新 `DeepSeek-V4.1-Flash-1017`（2026-10-17）を
  取得し、対象2ページを **stale** と判定（所要 約7秒・3リクエスト）
- イメージ内で `platform_watch` の解析と `main.DAILY_MISSION_TEMPLATE` の
  プレースホルダを実行確認（ECR `:latest` digest `sha256:a5984d00…`）
- favicon / apple-touch-icon は公開後の実URLとリポジトリの md5 が一致

## 5. 前提が変わったときの要注意事項

| 前提 | 崩れた場合に効くところ |
|---|---|
| Azure のカタログ一覧が `?search=` でHTMLを返す | `parse_entry_names` が0件になり `unknown`（「不明」）と出る。`LIST_URL` を見直す |
| モデルページに `Version: <!-- -->YYYY-MM-DD` がある | version が読めず `unknown`。`parse_meta` の正規表現を直す |
| ページが `Version <日付>` の形でカタログ版を書く | 書いていなければ `stale`（版の記載が無い）と判定する。表現を変えるなら `compare` を直す |
| 配布元は Azure の1社だけ | `TARGETS` に足す。見張らない配布元は**検知できない** |
| 当日の cache は12件程度 | 上限10件を超えると打ち切りが明示される。恒常的に超えるなら上限を上げる |
